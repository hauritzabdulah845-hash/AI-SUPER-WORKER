## 1. 竞品对标：追爆智能体 5 件套

| # | 竞品能力 | 说明 | 我方现状 |
|---|---|---|---|
| 1 | 文案三来源 | ①抖音链接提取文案 ②IP大脑（账号主页链接→分析风格→批量选题）③行业模板+AI 批量生成 | **空白**（LLM 通道已有） |
| 2 | 声音管理 | 上传 3-15s wav 做音色 | 素材库可存音频，**无角色语义** |
| 3 | 形象管理 | 上传 ~3min 模特视频做数字人形象 | 素材库可存视频，**无角色语义** |
| 4 | 素材管理+绑定 | 分镜素材 AI 分析 → 绑定话术 → 讲到即弹出 | 混剪工坊有**组**机制，无「口播段↔素材」绑定 |
| 5 | 合成数字人视频 + 任务管理 | 形象+声音+文案→数字人成片，进度队列 | **空白**（无口型合成能力） |

## 2. 硬约束（决定架构的事实）

1. **沙箱无 ffmpeg**（`ffmpeg-static` TLS 安装失败）→ 浏览器/服务端**不做转码**，合成链路沿用第四批模式：**方案 + SRT + 可执行脚本，本机出片**。
2. **不接真实第三方 API**（用户约定：功能与适配器先行，接入由用户后续完成）→ TTS 与数字人平台只做**适配器层 + 演示降级**。
3. **无口型同步自研能力**：lip-sync 需要模型（wav2lip 类或商业 API），不自研、不下载权重。
4. **肖像/声音合规**（红线沿用 prompts 约束）：形象素材必须自有或已授权；**不克隆他人音色**，TTS 只用平台官方音色；改写文案不照搬原文。
5. **不做桌面 RPA**（不抓微信/抖音客户端），链接类来源以「用户粘贴」为兑底。

## 3. 产品定位：四级能力阶梯

用户拿到的价值随接入深度递进，**每一级单独可用**：

```
L1 文案工坊（无 Key 即用）
   三来源 → 口播稿/分镜方案（LLM，降级模板标注）
      │
L2 本机合成（无 Key 即用，沿用混剪模式）
   方案 + SRT + ffmpeg 脚本（形象素材 + 已有配音/原声 + 字幕烧录）→ 本机出片
      │
L3 TTS 接入后（适配器就绪，等 Key）
   文案 → 自动配音（官方音色）→ 自动进入 L2 脚本链路
      │
L4 数字人 API 接入后（适配器就绪，等厂商）
   形象 + 文案/配音 → 平台口型合成 → 任务队列轮询 → 成片入作品库
```

- **L1+L2 是第八批可交付范围**（零外部依赖）；L3/L4 是适配器与队列骨架，**Key 到位即切换，不再改结构**。
- 竞品的「素材讲到即弹出」= 分镜里**口播主画面 + 绑定素材副画面（切镜/画中画）**，L2 脚本用 ffmpeg `overlay`/`switch` 表达，方案层先建模。

## 4. 模块设计

### 4.1 素材角色扩展（`media.ts` 向后兼容）

```ts
// MediaAsset 增加可选 role（老数据无 role = 普通分镜素材）
export type MediaRole = "avatar" | "voice" | "broll";
export interface MediaAsset { /* …既有字段… */ role?: MediaRole; }
```

- UI：素材卡新增角色徽标（形象/声音/分镜素材），下拉可改；**形象/声音上传时弹肖像与音色授权确认**（未确认不可设 role）。
- 分组约定不变：`group` 继续做场景组；`role` 是横切标注（一个形象素材可单独成组「形象」，也可不入组）。
- 查询辅助：`listByRole(assets, role)`。

### 4.2 文案三来源（来源C 的诚实降级）

| 来源 | 竞品 | 我方设计 | 依赖 |
|---|---|---|---|
| A 行业模板 | 行业分类→AI 批量 | 行业选择（美妆/餐饮/教育/家居/电商…）+ 定位 → LLM 批量出 N 条口播稿 | LLM ✓ |
| B 爆款改写 | 抖音链接提取 | **粘贴爆款文案** → LLM 拆结构（钩子/痛点/证据/CTA）→ 换题材重写（`content-repurposer` 红线：结构可复用、内容全新） | LLM ✓ |
| C IP大脑 | 账号主页链接 | **粘贴账号简介 + 作品标题列表**（链接抓取有 CORS/TOS 风险，降级为粘贴）→ LLM 分析风格 → 批量选题 | LLM ✓ |

- 来源 C 若后续要做真链接抓取：需自建代理服务——**列入接入清单，不做浏览器直抓**。
- 批量产出入「留档」（同混剪方案留档模式，`ai-employee:copy-drafts`，cap 20）。

### 4.3 口播方案（`DigitalPlan`，形状仿 `MixPlan`）

```ts
export interface DigitalSegment {
  order: number;
  script: string;          // 口播台词（该段原声/TTS 文本）
  duration: number;        // 预估秒数
  brollGroup?: string;     // 绑定素材组：该段讲到时切出的副画面（竞品"素材弹出"）
  subtitle: string;        // 字幕（≤16字，与台词同步）
}
export interface DigitalPlan {
  title: string;
  totalDuration: number;
  segments: DigitalSegment[];
  voiceVersions: string[]; // 多版本口播稿（矩阵分发防重复）
  assetHints: string[];    // 建议补拍/补传的素材清单
  demo: boolean;           // 模板降级标注
}
```

- 生成：`generateDigitalPlan({topic, industry, source, duration, avatarGroup?, brollGroups[]})` —— LLM 输出 JSON，**组名只允许来自给定组**（沿用混剪纪律），失败降级 `fallbackPlan(demo:true)`。
- 导出：`.md` 方案、`.srt`（`buildSrt` 直接复用）、**ffmpeg 脚本**：
  - L2 主链：`-i 形象素材 -i 配音音频` → `loop/trim` 主画面盖满音频时长 + `subtitles=` 烧录；
  - 有 `brollGroup` 的段落：`overlay` 按时间段切入副画面（时间段取该段 duration 累计）；
  - 无形象素材 → 退化为「分镜图片序列 + 配音」模板（与混剪 concat 模式一致）。

### 4.4 适配器接口（仿 `VideoProvider`，接入后置）

```ts
// L3：TTS
export type TtsProviderKind = "openai" | "volc" | "custom";
export interface TtsProvider {
  kind: TtsProviderKind;
  baseUrl: string; apiKey: string; model: string;
  voice: string;              // 只允许平台官方音色 ID（UI 下拉，不支持自由填他人音色）
}
export async function synthesize(p: TtsProvider, text: string): Promise<{ blob: Blob; duration: number }>;

// L4：数字人合成（通用 HTTP 形状，不预设厂商端点）
export type DigitalProviderKind = "custom";
export interface DigitalProvider {
  kind: DigitalProviderKind;
  baseUrl: string; apiKey: string;
  submitPath: string; pollPath: string;   // 路径映射可配，避免绑死厂商
}
// submit({ image|video, audio|text }) → { remoteId }；poll(remoteId) → { status, videoUrl }
```

- 配置存 localStorage（`supe-tts-provider` / `supe-digital-provider`），**与 video.ts 同模式**：通道配置本机、不入库。
- 无配置 → L3/L4 入口显示「接入后置」徽标，点击引导到适配器说明；**L1/L2 不受影响**。
- 任务队列复用 `supe-video` 模式的 IndexedDB store（`supe-digital` jobs：queued/running/succeeded/failed + 进度轮询），UI 挂在数字人工坊内。

## 5. 合规红线（写进代码与文案）

1. 形象素材上传时**必须勾选**「我确认拥有该形象的授权/为本人」才能标 `role=avatar`。
2. TTS 音色只提供**平台官方音色下拉**，不提供「上传他人声音克隆」入口。
3. 来源 B 改写走 `content-repurposer` 提示词红线：**结构可复用、内容全新、不照搬原句**；来源 C 不抓取原文，只做选题分析。
4. 生成方案保留「事实一致、禁编价格/承诺」纪律（沿用 `PLAN_SYSTEM` 约定）。
5. 合成脚本与成片仅本机；不做平台非官方直发（聚合发布边界不变）。

## 8. 适配器层交付记录（第九批，2026-11-24）

第八批 L1/L2 之后，第九批把 L3/L4 的**功能与适配器层**做完（Key 未到位即用演示形态，接入只差配置）：

### 8.1 L3 配音（`src/cloud/tts.ts`）
- `TtsConfig { provider: demo|generic, baseUrl, path, voice }` 存本机 `ai-employee:tts-config`；
- **demo**：`demoWav()` 本机生成合法 16bit PCM WAV（前 3 秒提示音，其余近静音），时长按文案 4 字/秒估算（2~60s）——保证 L2「形象+配音」链路端到端可跑；
- **generic**：POST 自配端点（body `{text, voice}`，期望音频二进制）——**不内置任何厂商签名**，火山/豆包按其文档配置即可；
- 生成的音轨走 `importMedia` 入素材库（不自动标 voice，仍需素材角色页勾授权后标注）。

### 8.2 L4 出片任务（`src/cloud/digitalhuman.ts`）
- `DigitalJob` 队列（本机留档 cap 10）：demo 任务 1.2s 自动推进 queued→running→done；完成提示指向 L2 ffmpeg 脚本（本机出片边界不变）；
- `DigitalProviderConfig { baseUrl, submitPath, pollPath, idField, statusField, doneValue }`：配置后 submit/poll 直连任意 JSON 服务，字段映射可配；提交失败记 `failed` 不吞错。

### 8.3 长文转口播（`digital.planFromArticle`）
- 方案来源新增「长文降维」：粘贴正文 ≥40 字 → LLM 结构化分镜；无通道降级 `heuristicPlanFromArticle`（按句切分→3~6 段装袋→时长归一→demo 标注），事实保留、禁编价格承诺。
