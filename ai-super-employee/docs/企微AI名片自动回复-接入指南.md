# 企微 AI 名片自动回复 · 接入指南

> 目标：客户在企微/微信里发消息 → 系统自动回复指定内容，或推送「AI 名片」小程序页面。
> 本文分三部分：能力边界 → 前置条件 → 两种落地方式（欢迎语 / 微信客服自动回复）。

---

## 一、能力边界（先看清楚，避免交付承诺出错）

| 场景 | 可行性 | 限制 |
|---|---|---|
| 客户加好友 → 自动发欢迎语 + 小程序名片 | ✅ 后台配置即可 | 无 |
| 客户在「微信客服」发消息 → 自动回复内容/名片 | ✅ API 完整支持 | 需企业认证 + 回调服务 |
| 好友私聊读内容再智能回复 | ⚠️ 受限 | 需会话存档（付费 + 审核） |
| 主动群发给客户 | ⚠️ 强限制 | 每客户每月 4 条，需员工确认 |
| 给企业内部员工推送 | ✅ 完全开放 | 无（自建应用消息） |

结论：**「按用户回复自动发名片」走微信客服通道是唯一合规且完整的路径。**

---

## 二、前置条件清单（缺一项就跑不通）

| # | 项目 | 从哪里拿 | 状态 |
|---|---|---|---|
| 1 | 企业微信已完成**企业认证** | 企微管理后台 → 我的企业 → 企业信息 | ☐ |
| 2 | 企业 ID（`corpid`） | 我的企业 → 企业信息 → 企业 ID | ☐ |
| 3 | 微信客服 **Secret** | 应用管理 → 微信客服 →  Secret | ☐ |
| 4 | 微信客服账号 ID（`open_kfid`，形如 `wkxxxx`） | 微信客服后台 → 客服账号 | ☐ |
| 5 | 回调 **Token** 与 **EncodingAESKey**（43 位） | 微信客服 → 接收消息服务器配置页自行生成 | ☐ |
| 6 | 小程序 **AppID** 与名片**页面路径**（如 `pages/card/index`） | 微信公众平台 → 开发管理 | ☐ |
| 7 | 小程序**已发布上线**（体验版/开发版发不出卡片） | 微信公众平台 | ☐ |
| 8 | 小程序与企微**同主体或已关联** | 微信开放平台 / 企微后台关联小程序 | ☐ |
| 9 | 一个 **HTTPS 域名**（回调地址必须是 80/443，需备案） | 你的服务器/云托管 | ☐ |

> 提示：1-5、8 都能在企微后台自助完成；6-7 在微信公众平台；9 如果暂时没有域名，可以先用内网穿透工具联调，正式上线再换。

## 三、方式一：欢迎语自动发名片（零开发，今天生效）

适用于「客户刚加好友」的第一次触达。

1. 登录 [企微管理后台](https://work.weixin.qq.com) → **客户与上下游 → 客户联系 → 欢迎语**
2. 点击「配置欢迎语」，选择作用范围（全员 / 指定成员 / 指定部门）
3. 添加一条**文字**：一句自我介绍 + 引导语（例：「你好，我是 XX，点开下面的名片可以先看看我们能帮你做什么」）
4. 再添加一条**小程序**：选择你的 AI 名片小程序 → 填写标题与页面路径
5. 保存后，用另一个微信号添加一位成员的企业微信，验证收到的内容

注意事项：
- 欢迎语只在**首次添加好友**时触发，老客户不会收到
- 小程序必须已发布，且与企微主体一致/已关联，否则选择列表里看不到
- 欢迎语支持文字、图片、小程序、网页、文件五种类型，可按成员分别配置

## 四、方式二：微信客服 AI 自动回复（本仓库 `wecom-kf-service`）

适用于「客户主动咨询 → 按内容回复指定文案或名片」。

### 4.1 流程

```
客户在微信里给「微信客服」发消息
        ↓
企微回调通知（加密 XML，5 秒内必须响应）
        ↓
服务调 sync_msg 拉取消息内容
        ↓
规则匹配（关键词）→ 未命中走 AI 意图判断
        ↓
调 kf/send_msg 回复：文本 或 小程序名片
```

### 4.2 部署

```bash
cd wecom-kf-service
cp config.example.json config.json   # 填入第二节拿到的参数
npm start                            # 默认监听 8787
```

把 `https://你的域名/wecom/callback` 填到企微「微信客服 → 接收消息服务器配置」，
Token 与 EncodingAESKey 必须与服务端 `config.json` 完全一致。

### 4.3 规则配置（rules.json）

```json
[
  { "id": "card", "keywords": ["名片", "介绍", "你是谁", "了解"], "reply": { "type": "miniprogram" } },
  { "id": "price", "keywords": ["价格", "多少钱", "报价"], "reply": { "type": "text", "content": "我们的价格体系如下：……" } },
  { "id": "fallback", "isDefault": true, "reply": { "type": "text", "content": "收到，我稍后回复你。也可以先点开名片看看。" } }
]
```

- 关键词匹配规则：完全相等或包含即命中，按数组顺序优先
- `reply.type = "miniprogram"` 时使用 `config.json` 里的 `miniAppId` / `miniTitle` / `miniPagePath`
- 可开启 `aiFallback`：规则都没命中时，让 DeepSeek 在规则列表里挑一个意图，挑不出就用默认回复

### 4.4 本地自测

```bash
node test/run-test.mjs
```

测试会用真实加解密算法构造回调包，验证：签名校验 → 解密 → 消息同步 → 规则命中 → 回复报文（mock 模式不真发消息）。

## 五、常见坑

1. **回调必须 5 秒内返回**：先回 `success`，再异步处理，否则企微会重试并可能停用回调
2. **微信客服回调只给通知，不带正文**：必须用回调里的 `Token` 调 `sync_msg`，该 Token 有效期 6 分钟
3. **cursor 必须持久化**：`sync_msg` 返回 `next_cursor`，丢了会重复收消息
4. **access_token 缓存 7200 秒**：每次都重新取会被限频
5. **群发不是私聊**：想「主动推给所有客户」只能走群发助手且每月 4 条，还需要员工确认
6. **小程序发不出去**：90% 是未发布或主体未关联

---

## 六、合规红线

- 不绕过微信客服通道做「私聊机器人」，会被封禁接口权限
- 自动回复内容不得含绝对化用语、功效承诺（沿用平台风控岗位的红线）
- 客户消息属个人信息，落库需最小化，不导出、不跨客户复用
