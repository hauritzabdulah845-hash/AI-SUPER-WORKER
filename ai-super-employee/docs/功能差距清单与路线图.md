## 一、一句话结论

**本仓库是那份 400 功能点目录的「多智能体任务 + 线索 + 知识库 + 企微」核心 Web 子集**，
不是完整产品。已实现的 11 个控制台模块功能闭环较完整、可运行；但目录里约 **6 成功能域在仓库中完全不存在**（视频、声音/数字人、媒体发布、桌面微信自动化、会议、人事、法务 GEO、企业设置管理）。

## 三、已实现模块内部的缺口（同域内的「最后一公里」）

| 模块 | 缺口 | 影响 |
|---|---|---|
| 任务中心 | 失败原因只在详情里可见，无失败重试统计视图 | 排障靠翻列表 |

## 四、路线图（按优先级）

### P0 —— 让已有功能「真的能用」（不做，前面的功能都是摆设）

| # | 事项 | 现状 / 验收标准 | 依赖 |
|---|---|---|---|
| P0-1 | **登录链路实测**：手机号 OTP 本地走通；OAuth 明确「仅已发布域名可用」写进文档 | 本地 `localhost:5173` 能收到验证码并进入控制台 | 用户真实浏览器 + 云服务配置 |
| P0-2 | **模型通道可用性**：平台通道 429 时给出醒目引导，一键跳「模型接入」配置自定义 Key；补配额/消耗统计 | 任务执行前能预知通道是否可用，不再跑到一半失败 | 云服务配额确认（WorkBuddy 控制台） |
| P0-3 | **多租户 RLS 落地**：`scripts/rls-isolation.sql` 逐表执行并回归 | 用 A 账号写的数据，B 账号查不到（含直接拿 publishableKey 调接口） | 应用属主账号登录云控制台 |
| P0-4 | **企微真环境联调**：corpid / 客服 Secret / open_kfid / Token / AESKey / 小程序 appid / HTTPS 域名 | 真机发消息→自动回复→控制台同步出线索与对话 | 客户提供 7 项参数 |
| P0-5 | **企微 P0 遗留**：① 转人工兜底（未命中→通知接待人员）② 客户进会话欢迎语（`welcome_code`） | 自测脚本各加 1 项用例并通过 | 无 |

### P1 —— 补齐核心域的高频缺口（决定「像不像完整产品」）

| # | 事项 | 说明 |
|---|---|---|
| P1-1 | 域 06 聚合发布（最小版）：内容工厂产出 → 复制/导出到公众号·小红书·抖音草稿 + 定时提醒 | 先做「人工发布助手」，平台授权自动化放 P2 |

| P1-3 | 域 12 设置：成员与权限、品牌业务配置、模型价格目录 | 企业采购的硬性要求 |

| P1-6 | 用量看板：Token 消耗、任务费用、通道成功率 | 与 P0-2 同源数据 |

### P2 —— 新功能域（每个都是独立工程量）

1. **域 04 视频创作**：先接 1 家（如 Seedance）跑通「统一视频生成」，再扩多模型。
2. **域 05 声音/数字人**：语音合成 → 声音复刻 → 数字人，依赖供应商能力。
3. **域 08 桌面微信自动化**：需 Windows 本机客户端 + 授权，与现有企微客服服务是两条线。
4. **域 09 会议 / 域 10 人事**：依赖会议平台与招聘平台账号授权。
5. **域 13 法务 / GEO**：合同审查可先用现有任务编排 + 法务岗位模板做 MVP。

### P3 —— 工程质量（随版本顺手做）

- 重写根 `README.md`（当前仍是 Vite 模板文案，新同学上手无从下手）

- 浏览器端到端回归（Playwright）：登录墙、11 个模块首屏、导入、任务执行
- 错误上报与会话回放（当前失败只靠 toast）
- 企微同步游标与去重上限复核（服务端事件流 2000 条、前端查重读 500 条的边界场景）

## 五、竞品功能对照（百付AI「AI超级员工」，2026-11-24 调研）

来源：`https://www.baifuai.com/product/showproduct.php?id=4` —— 与我们**同名**的竞品，主打「AI获客 + AI引流 + AI销售」三位一体。
关键判断：**它宣传的功能，几乎正好是我们路线图里 P1/P2 的缺口**，且客户版功能目录 PDF 本来就承诺过同批能力（04 视频 / 05 追爆·混剪 / 06 聚合发布 / 13 GEO）——所以「可不可以加」的答案是**可以，而且应该加**，分歧只在做多深、按什么顺序。

### 5.1 对照表

| 竞品功能 | 我们现状 | 可行性 | 落点 |
|---|---|---|---|
| **Sora2 / Seedance / Veo 短视频**（文生/图生/首尾帧，批量+1080P） | ❌ 域 04 完全没有，但 `canvas.ts` 已有「提交任务→轮询→取结果」的生图通道层可复用 | 🟡 B 类：**Seedance（火山方舟 API）最可行**；Veo 有地区/支付门槛；Sora2 官方 API 开放度最低 | 新增 `src/cloud/video.ts` 仿照 `canvas.ts`，控制台加「视频创作」模块 |
| **一键聚合发布**（抖音/快手/视频号/小红书/B站，AI 标题标签自动分发） | ❌ 域 06 没有；内容工厂产出只能复制/导出 | 🟡 B 类：**先做半自动版**（AI 生成各平台标题/标签/话题 + 发布清单 + 定时提醒，零授权风险）；官方 API 自动发布需逐平台企业授权 | 路线图 P1-1 的升级版 |
| **GEO 智能体**（优化内容让 DeepSeek/豆包主动推荐企业） | ❌ 域 13 没有；但我们已有 LLM 通道层 + 知识库 | 🟢 **A 类，纯软件、零外部依赖，性价比最高** | 新增「GEO 工作台」：站点/资料体检 → 生成结构化 FAQ·问答体内容 → 用多模型跑测试提示词、跟踪品牌提及率 |
| **追爆智能体**（贴抖音链接→拆解爆款→仿写文案→配数字人+克隆声） | ❌ | 🟡 B 类：**文案拆解/仿写部分可立即做**（LLM 能力已具备，链接抓取脆弱且有 ToS 风险）；数字人/声音克隆需第三方 API | 拆成「爆款拆解→仿写脚本」先上，影像合成后接 |
| **短视频混剪**（素材分组、文案润色、转场/字幕/BGM 自定义） | ❌ | 🟡 B 类：浏览器端做不了重转码，**需要 FFmpeg 服务端 worker**（新建 sidecar 服务，模式同 `wecom-kf-service`）；前提是先有素材库（域 06 素材库） | 新增 `media-worker` 服务 + 素材库模块 |
| **抖音AI客服**（私信 7×24 自动接待引导留资） | ⚠️ 我们只有**微信客服**侧的 AI 接待（`wecom-kf-service`，已 15/15 自测） | 🟡 B 类：需抖音开放平台企业授权，架构可直接复用 rules/客户档案/事件流那套 | 把 `wecom-kf-service` 泛化成 `kf-service` 多渠道 |
| **抖音留资手机号 → 自动加好友（快手/小红书/B站扩展）** | ❌ | 🔴 **C 类，不建议按对方做法做**：个人微信协议加好友 = 封号 + 违反平台协议；抖音手机号自动加微同理 | 只做合规版：留资 → 进 `leads` 表 → 企微侧用**官方客户联系 API** 发起会话 |
| **智能私域管家 / 高意向实时提醒**（识别高意向信号→提醒人工→自动改标签） | ⚠️ 半有：线索意向/阶段、`guessStage` 粗判、跟进回填都有，但**没有实时提醒、没有自动改标签** | 🟢 **A 类，增量改造现有模块** | 服务端 `guessStage` 命中「报价/成交」→ 推企微群机器人 webhook + 控制台通知；`intentOfStage` 联动更新线索意向 |
| **飞书 / 微信小程序下指令**（一句话让电脑上的 Agent 干活） | ⚠️ 只有 Web 控制台 + ⌘K；任务编排（`runner.ts`）已完备 | 🟡 B 类：**飞书机器人入口成本低**（新建 sidecar 收 webhook → 调云端任务 → 回卡片）；小程序是独立前端工程 | 新增 `bot-gateway` 服务 |
| **RPA 模拟人工 + 本地部署 + 知识库加密** | ❌ | 🔴 C 类（RPA 自动化他人平台 = 封号风险）/ 🟡 本地部署与加密是独立交付工程（打包 + 客户端加密再上传） | 单列「私有化交付」工作流，不与功能开发混排 |

图例：🟢 A 类 = 纯软件、现有架构直接承载 ｜ 🟡 B 类 = 可做，但依赖第三方 API/授权/新 worker 服务 ｜ 🔴 C 类 = 对方做法有封号与合规风险，只做合规替代。

### 5.2 结论与建议顺序

1. **先做 A 类**（GEO 工作台、高意向提醒、聚合发布半自动版、爆款文案拆解）—— 零外部依赖、1~2 周量级，直接把竞品「最有感」的两个功能变成我们的。
2. **B 类逐个接**：Seedance 视频（付费 Key 即可）→ 抖音客服（需开放平台授权）→ 混剪 worker（需素材库先行）→ 飞书入口。
3. **C 类只做合规替代**：留资进线索表 + 企微官方 API 触达，绝不做协议加好友与批量私信 RPA。
4. 竞品页面上的量化承诺（人力成本 -50%、转化 +40% 等）是营销话术，没有可核验口径——**不要写进我们对客户的材料**。

## 十、第四批交付：素材库 + 混剪工坊（域05视频生产 + 域03素材管理）

### 10.1 模块与能力
- **素材库**（`src/cloud/media.ts` + `MixStudio` 左栏）：本机素材（视频/图片/音频）导入归组、分组徽标展示、组内计数、删除；素材以 **Blob 存 IndexedDB**（库名 `supe-media`），不进业务库不进 Git、不上传任何服务器。
- **混剪工坊**（`src/cloud/mixcut.ts` + `MixStudio` 右栏）：
  - 输入：目标主题、风格（口播向/剧情向/节奏卡点/纯字幕）、成片时长（15/30/60）、配音版本数（2 或 3）、参与的素材组；
  - 输出**分镜级方案**：逐镜头 `素材组 → 转场 → 镜头说明 → 字幕(≤16字) → 时长`，首镜强制 3 秒钩子，总时长严格等于所选时长；
  - **配音多版本**：同一方案产出 N 个 30 秒口播文案（开场钩子→产品事实→行动指令），事实一致、禁编价格/承诺；
  - 取材规则：组名只允许来自用户已归类的组，**取不到材的组在方案中被丢弃**（组名非法过滤），导出时统计空组并提示。

### 10.2 本机出片链路（可执行脚本导出）
- 交付物：方案 `.md`、字幕 `.srt`、**ffmpeg 脚本 `.sh` / `.bat`**（脚本头部写明用法与输出路径）。
- 脚本两档：
  1. **trim 模式**（组内素材时长都探测到时默认）：`filter_complex trim+concat`，每个镜头精确裁到方案时长（`cap=min(场景时长, 素材时长)`）+ 字幕滤镜；
  2. **concat 模式**（时长探测不到或 filter_complex 失败兜底）：concat demuxer `-c copy` 粗拼 + `subtitle` 软字幕（`force_style` 走样式覆盖，规避 `-vf`/`-filter_complex` 叠加的 `Parsed_` 前缀兼容问题）。
- **素材定位**：脚本按「当前工作目录」找素材——把本机素材与脚本放同一目录（或 `cd` 到素材目录）运行即可；缺素材/空组会在脚本里跳过并回显。
- **本机要求**：ffmpeg ≥ 5（macOS: `brew install ffmpeg`；Windows: 官网包加 PATH）。运行前先「手动预览几秒」确认素材与分镜对得上。
- 明确边界：**沙箱/浏览器不做视频转码**——生成器只产方案与脚本，真正出片在用户本机执行；没有 ffmpeg 就把 `.md`+`.srt` 导进剪映/PR 手动剪。

### 10.3 验证记录
- `npm run test:mixcut`（新增，`scripts/mixcut-check.ts`，tsx 直跑）：**13/13**——SRT 时间轴（无字幕镜头也占位、起止秒正确）、trim 模式选材与 `trim=0:x.xx` 裁剪、空组跳过、**无裸反斜杠转义**（曾实测定位的 shell 引号坑）、bat `^` 续行、时长未知降级 concat、Markdown 分镜表与降级标记。
- 回归：`lint` 0、`build` 通过、`wecom-kf-service` 16/16、`im-bot-gateway` 16/16；`MixStudio.tsx`/`media.ts`/`mixcut.ts`/`nav.ts` 由 Vite 转换 200。
- 过程中修复 2 个实现 bug（镜头取素材时误引用分组对象；filter_complex 连接符在 shell 双引号内产生字面反斜杠），均由自检覆盖防回退。

### 10.4 接线与使用路径
控制台 → 侧边栏「混剪工坊」→ 上传素材并按场景归组 → 填目标/风格/时长/配音版本/选组 →「生成方案」（模型不可用自动降级并标注）→ 复制配音文案 / 下载 .md / .srt / .sh / .bat → 本机 `bash build-mix.sh` 出片。

### 10.5 边界（不做 / 留待后续）
- 不做浏览器内转码与云端渲染（沙箱无 ffmpeg、出片算力在本机）；
- 素材不上传、不进 Git（Blob 仅存本机 IndexedDB，换浏览器/清缓存需重新导入——方案与脚本可下载留档）；

- BGM 目前只在方案中标注建议，脚本不自动混音（避免版权与音量纠纷），需要时在剪映/PR 里加。

### 11.2 真实差距（合规可做，按价值排序）

1. **P0 · 定时任务流水线（"总控开关"）**：竞品把短视频曝光、微信智能体、抖音客服等多智能体串成一键启动的协同流水线。我方有发布排期+任务队列，**缺跨模块定时编排**（例：每天 9:00 生成视频→10:00 GEO 检查→12:00 排期发布→18:00 高意向复查）。

5. **P1 · 地图获客**：高德授权→按地区/关键词采集商家→leads→自动加好友。我方无地图渠道；**高德官方 API 合规可做**，自动加好友一步按红线只留「一键跳转企微官方加粉/生成加微话术」。

8. **P2 · 企微主动激活补齐**：竞品企微版含群发（普通/定时、按标签）、白名单/黑名单、自动备注、意向用户提醒、附件管理（关键词→发文件）。我方 `wecom-kf-service` 只有回复链路，**缺群发计划与名单管理**（企微官方 API 均支持）。

10. **P3 · 媒体账号扫码授权**：竞品「添加账号→扫码登录→授权→同步」。我方渠道为手动配置；抖音开放平台 OAuth 属官方接入，按约定留待用户后续接入，届时加「扫码授权+同步」壳。
