## 二、⚠ 本轮验收发现并修复的真 Bug（2 处，同源）

**现象**：数字人 / 混剪导出的 ffmpeg 脚本，**只要带分镜图或副画面，命令就会断成两条**，本机执行必然失败——但 `bash -n` 语法检查通过、原有测试只查字符串片段，所以八批以来一直没被发现。

**根因**：`inputs.forEach((input, index) => lines.push(... index === inputs.length - 1 ? "" : cont))` —— 最后一个输入行不加续行符，但后面紧跟 `-filter_complex`。

| 修复 | 位置 |
|---|---|
| 每个输入行都加续行符 | `src/cloud/digital.ts`（数字人） |
| 同上 | `src/cloud/mixcut.ts`（混剪） |
| 新增结构性测试：命令每行必须以续行符结尾 | `scripts/digital-check.ts`（sh+bat）、`scripts/mixcut-check.ts`（sh+bat） |
| 重出验收样例 | `acceptance-samples/make-digital.sh` / `.bat` |

**已做回退验证**：把 bug 改回去，新测试立即报 `✗ 未续行: -loop 1 -i "分镜1.png"` —— 测试真的能抓。

> 这正是「本机验收」的价值：跨十二批的代码层测试全绿，仍然漏了一条只在真实执行时才炸的命令链。
