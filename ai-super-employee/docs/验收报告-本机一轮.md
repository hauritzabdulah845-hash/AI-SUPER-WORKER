## 二、⚠ 本轮验收发现并修复的真 Bug（2 处，同源）

**现象**：数字人 / 混剪导出的 ffmpeg 脚本，**只要带分镜图或副画面，命令就会断成两条**，本机执行必然失败——但 `bash -n` 语法检查通过、原有测试只查字符串片段，所以八批以来一直没被发现。

**根因**：`inputs.forEach((input, index) => lines.push(... index === inputs.length - 1 ? "" : cont))` —— 最后一个输入行不加续行符，但后面紧跟 `-filter_complex`。

| 修复 | 位置 |
|---|---|
| 每个输入行都加续行符 | `src/cloud/digital.ts`（数字人） |
| 同上 | `src/cloud/mixcut.ts`（混剪） |
| 新增结构性测试：命令每行必须以续行符结尾 | `scripts/digital-check.ts`（sh+bat）、`scripts/mixcut-check.ts`（sh+bat） |
| 重出验收样例 | `acceptance-samples/make-digital.sh` / `.bat` |

**已做回退验证**：把 bug 改回去，新测试立即报 `✗ 未续行: -loop 1 -i "分镜1.png"` —— 测试真的能抓。

> 这正是「本机验收」的价值：跨十二批的代码层测试全绿，仍然漏了一条只在真实执行时才炸的命令链。

## 四、C 组出片实测（沙箱内真跑，已通过）

沙箱原本无 ffmpeg，本轮通过 npm 装了静态版（`@ffmpeg-installer/ffmpeg`，**自带 libass + libfreetype**），
配合从 npm 转出的 Noto Sans SC 字体，**把 C 组完整跑通了**。

### 4.1 又发现并修复两个真 Bug

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| **3** | `Could not find tag for codec pcm_s16le` → **出片直接失败** | `-c:a copy` 把 wav 原样塞进 mp4，mp4 容器不支持 PCM | wav/aiff/pcm 自动转 `-c:a aac -b:a 192k`；mp3/aac 仍 copy |
| **4** | 中文字幕显示为**方块 / 带叉方框** | 字体名写死 `Microsoft YaHei`，非 Windows 机器没有 → libass 回退到无中文字形的字体 | 生成器支持 `fontName` + `fontDir`（滤镜带 `fontsdir=`），脚本尾部给出中文提示 |

> ⚠ 关于「逗号候选字体列表」：我一开始以为 libass 支持 `FontName=A,B,C` 的候选回退，**实测证明不支持**
> （`NoSuch,DejaVu Serif` 渲染结果 = DejaVu Sans，而不是 Serif）。已回退该方案，改为 `fontsdir` + 单一字体名。

### 4.4 字体问题的正确姿势（写进清单了）
1. libass 只认**单一字体名**，不认逗号候选列表。
2. 字体**文件名无所谓**，匹配的是字体内部的 family 名：`fc-scan --format "%{family}" 字体.ttf`。
3. 最省事：把中文字体放进脚本同目录 `fonts/`，脚本已带 `fontsdir=fonts`，不装系统也能用。
