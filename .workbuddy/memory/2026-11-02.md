## 启动项目.bat 修复（09:12-09:50 段）
用户反馈双击启动失败。三层原因，全部修复：
1. **换行符是 LF**：cmd 要求 CRLF，LF-only 会让括号代码块解析错乱 → 重写为 CRLF（纯 ASCII 内容，无编码风险）。
2. **Node 不在系统/用户 PATH**：node 只装在 `%USERPROFILE%\.workbuddy\binaries\node\versions\22.22.2-6\`，WorkBuddy 终端会话有 PATH 注入而 Explorer 双击环境没有 → `where npm` 失败直接报错。修复：bat 自动按序查找（where npm → .workbuddy binaries 通配 → Program Files → LocalAppData），找到后把 node 目录注入本次会话 PATH。
3. **代码块内 echo 文本含裸 `)`**：`echo (first run only, ...)` 里的右括号把 if 块提前关闭，导致 `npm install` 每次启动无条件白跑 18-30 秒、[Setup] 提示永不显示 → 去掉括号。
- 验证方式：`cmd //c "set PATH=System32;Windows && 启动项目.bat"` 模拟无 npm 的双击环境；修复后 2 秒内 vite ready、端口 5173 返回 200。
- 经验：cmd 批处理括号块内 echo 不能含未转义括号；排查 bat 要看实际字节（LF/括号），不能只看内容对不对。
